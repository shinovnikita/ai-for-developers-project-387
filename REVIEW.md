# Критерии независимого ревью

- Сопоставить поведение и границы PR с исходным обращением, спецификацией,
  тикетами и последним человеческим согласованием. Недоступные ссылки и
  несогласованное расширение объёма явно перечислить.
- Проверить TypeSpec, штатную генерацию OpenAPI/SDK и независимую серверную
  валидацию; сгенерированные файлы не исправляются вручную.
- Сохранить часовой пояс, окно записи, рабочее время, запрет пересечений,
  смежные встречи, атомарность параллельных запросов и повторные попытки.
- Проверить открытие старой SQLite, отсутствие потери встреч, безопасное
  повторное открытие и сохранение данных после перезапуска.
- Для реализации #7 проверить согласованные правила темы: trim, 1–200 Unicode
  code points, ошибки формы/API, полный текст и длинные слова на узком экране,
  тему из ответа сервера, отсутствие темы старых встреч, порядок проверки
  attemptId и неизменность сохранённой попытки. Учитывать этап #8 → #9.
- Проверить основной, негативный и соседний сценарии на подходящих уровнях;
  браузерный путь использует настоящий сервер. Оценить риск и достаточность
  глубины проверки, а не только число тестов.
- Сверить доказательства CI и отдельный браузерный артефакт с полным текущим
  pull_request.head.sha. Старые/пропущенные проверки не подтверждают новый SHA.

Публиковать только подтверждённые замечания с местом, условием и последствием.
При отсутствии замечаний назвать проверенные сценарии и ограничения.
Всегда указать полный проверенный SHA. Ревьюер не изменяет код, не запускает
implement-spec и не решает вопрос слияния.
