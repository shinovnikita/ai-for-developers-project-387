# Domain Docs

This repo has a single domain context shared by the frontend and backend.

## Before exploring the codebase

- Read `GLOSSARY.md` at the repository root for domain terminology.
- Read the ADRs in `docs/adr/` that cover the area you will work on.

If the glossary or ADR directory is absent, continue silently. Use `/domain-modeling` to create the glossary when the first term is agreed and to record the first ADR when a decision warrants one.

## Use the glossary's vocabulary

Use the glossary's terms in issues, tests, and design proposals. When a term is missing, check the language already used in the project and bring any unresolved terminology to `/domain-modeling`.

## Flag ADR conflicts

If a proposal contradicts an ADR, name the ADR and explain why the decision should be reopened.
