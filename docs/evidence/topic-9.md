## Проверенные границы

- HTTP: обязательная строка; независимые trim и 1–200 Unicode code points;
  границы с emoji и combining marks; ошибки структуры и содержимого с
  `fieldErrors.topic`; отклонённые запросы не создают встреч.
- Атомарная запись темы с остальными данными; одинаковая тема в подтверждении и
  списке. Прежняя схема SQLite с отдельной старой записью без темы, создание новой
  через HTTP и два повторных открытия файла проверяются через публичный API.
- Повтор сравнивает нормализованные данные до проверки новой записи. Краевые
  пробелы эквивалентны; регистр, внутренние пробелы, пустая и длинная изменённые
  строки дают `409`; неверные типы/отсутствие — `400`. Старую запись нельзя дополнить
  темой. Восстановление сохраняется после начала встречи и сдвига окна записи.
- Браузер: нет POST при локальных ошибках; после исправления — настоящий `201`;
  реальные серверные ошибки у поля; обязательность и Unicode-границы формы;
  подтверждение использует серверную тему, отличную от локального черновика.
- Главная → запись → подтверждение → владелец, 200 code points на экране 320px,
  полный текст и длинное слово без обрезки, HTML как текст, обновление/перезагрузка.
  Отдельная старая запись показывает «Тема не указана».
- Потеря реального ответа после сохранения: тот же полный payload, тема и attemptId,
  `200`, прежняя встреча без дубля. Редактирование темы начинает новую попытку;
  прежняя встреча остаётся неизменной, смежный свободный слот бронируется.

Успешные ответы не подменяются. В тесте источника подтверждения изменяется только
исходящий запрос; ответ, сохранение и чтение выполняет настоящий сервер.
Сгенерированные файлы штатно обновлены командами проекта и, согласно `.gitignore`,
не отслеживаются Git. Отдельный CI-артефакт браузерного отчёта привязывается к SHA
доверенным workflow; эти локальные логи не выдают себя за результат CI.
